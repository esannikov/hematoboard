# HematoBoard Dashboard

Публічний статичний переглядач підготовлених і знеособлених клінічних
пакетів для доказового обговорення складних гематологічних випадків.

**Live dashboard:** <https://esannikov.github.io/hematoboard/>

**CASE006:**
<https://esannikov.github.io/hematoboard/?case=case006&view=overview&release=20260810case006ledgerrebuild1>

## Поточний реліз

Реліз `20260810case006ledgerrebuild1` перестворює CASE006 з нової прийнятої версії
`CASE006@6ec73b7e806a`. Accepted bundle містить 58 адресованих спостережень, а hash-pinned
кандидатна reasoning revision відображається в Огляді як робоча гіпотеза, диференційний
ряд і план діагностичної верифікації — окремо від прийнятого стану. Повна
проєкційна перевірка підтвердила однакову множину observation IDs, точне
відтворення клінічних полів і семантичне замикання кожної поверхні. Період
походить лише з дат клінічних записів; граф показує 28 candidate relations,
карта — 8 прогалин і 5 кроків верифікації, а дослідження — точні категорії
58 прийнятих спостережень. 23 якісні записи валідуються як точні display-твердження;
50 записів без прийнятої точної дати не підміняються OCR-припущеннями й лишаються поза хронологією.

Клінічне прийняття кандидатного синтезу CASE006 залишається очікуваним.
Інтерфейс показує цей статус і не надає кандидатові повноважень змінювати
accepted ledger.

Поточний машинний release receipt: [`release.json`](./release.json).

## Що показує переглядач

- огляд прийнятого стану й окремої кандидатної інтерпретації;
- хронологію документів і клінічних подій;
- типізовані зв'язки між фактами та гіпотезами;
- дослідження, джерела, прогалини й план верифікації;
- протокол формування синтезу та його вхідні хеші;
- стислий клінічний пакет для обговорення.

Реєстр кейсів читається з `active_cases.json`, а клінічний зміст — із
валідованих `case_bundle.json` і дозволених hash-pinned reasoning artifacts.
Рендерер не містить case-specific клінічних тверджень.

## Межа публічних даних

Репозиторій містить статичний переглядач, локальні шрифти, чотири
знеособлені пакети, дозволені похідні та мінімальні артефакти, необхідні для
read-only проєкції. Оригінальні PDF, OCR, ідентифікатори, source crops,
ліцензовані настанови, приватні receipts, журнали аудиту й clinician-review
runtime не публікуються.

HematoBoard підтримує структуровану перевірку та клінічне обговорення.
Остаточна клінічна відповідальність залишається за відповідальним лікарем після
перегляду повного первинного запису.
